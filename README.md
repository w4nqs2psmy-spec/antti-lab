# Antti Lab — personal portfolio starter

A responsive, static portfolio site made with plain HTML, CSS and JavaScript. The rainy city-window hero is drawn on a native canvas, with no Spline embed, framework, build step, API key, subscription or external image/font service.

## What to personalize first

The visual design and all six sections are in place. Before making the site public, spend a few minutes replacing the starter content with your own:

1. In `index.html`, adjust the About introduction, AI Lab experiments, research themes and teaching description to match your actual work.
2. Replace the three sample concept cards in **Selected Projects** with real projects. Add links and screenshots when you have them. The current cards are explicitly marked as starter concepts.
3. Replace `hello@example.com` in the contact button with your email address, or remove the button if you prefer not to publish an email.
4. Update the page title and description near the top of `index.html` if you change the site name.

To preview it on your computer, open `index.html` in a browser. You can edit the files in any text editor; no install step is needed.

## Publish with GitHub Pages

### 1. Create your repository

Sign in at [github.com](https://github.com), choose **New repository**, and create a public repository named `antti-lab` (or any name you prefer). With a free GitHub account, Pages publishing requires a public repository. Keep this project as a dedicated portfolio repository.

If you want the shorter address `https://YOUR-USERNAME.github.io/` instead of a project address, name the repository exactly `YOUR-USERNAME.github.io`.

### 2. Upload the site files to the repository root

Open the new repository and choose **Add file → Upload files**. Open this `antti-lab` folder on your computer and upload its contents: `index.html`, `styles.css`, `script.js`, `favicon.svg`, and `README.md`. Upload the files themselves at the top level of the repository; do not put them inside an extra `antti-lab` folder. Commit the upload to the `main` branch.

### 3. Turn on GitHub Pages

In the repository, open **Settings → Pages**. Under **Build and deployment**, set **Source** to **Deploy from a branch**, choose **main** and **/(root)**, then select **Save**.

### 4. Open the published site

Return to **Settings → Pages** and use **Visit site** once GitHub finishes publishing. For a repository named `antti-lab`, the address will be:

```text
https://YOUR-USERNAME.github.io/antti-lab/
```

The first publish can take several minutes. Later, upload and commit any edits to `main`; Pages republishes them automatically.

## Keep it yours

The complete source is the files in this folder. Download or clone the repository whenever you like, and keep a copy on your computer. The site itself uses browser-native features only. GitHub Pages hosts the public files; you do not need Spline hosting or a Spline subscription for this version. A custom domain is optional and has to be registered separately.

For the current GitHub Pages screens and publishing options, see GitHub’s official guides: [create a Pages site](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site) and [choose a publishing source](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).
